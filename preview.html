Before you explore

A few quick things:
Fan-made project
This is an unofficial, fan-made tool. It is not affiliated with, endorsed by, or sponsored by Hello Games.
Procedural data
Star systems are generated procedurally from their portal address, the same way the game does -- they are not scraped from anyone's real save. Star type, system/region names, and total planet+moon count are all reverse-engineered from the game's own logic and right most of the time, but they're a corpus-verified approximation, not a perfect decompile -- occasional mismatches (e.g. a system that generates as 5 bodies but is really 3 in your save) are a known, expected gap, not a bug to report. Individual planet names are not accurate at all -- the real game's planet-naming logic has never been fully reverse-engineered (confirmed against the game's own decompiled data and a real save file), so what you see is a plausible guess, not your actual save data. As of 2026-08-18 that guess leans on the planet's own biome (and Sentinel activity, once known) to pick a more fitting-sounding name -- still a guess, just a less randomly-mismatched one. Importing your save file only ever pulls in real base names (a save doesn't expose anything else about a system) -- everything else, including fixing a wrong planet count, still needs typing in by hand via Edit system. A system only reflects real in-game data once a traveller has entered it that way, marked "Community edited".
Star class letters (e.g. "G7p")
The letter is the spectral class (matches star colour) and the digit is a sub-class. The lower-case suffix -- f, p, or pf -- borrows real astronomy terms (p = "peculiar", an unusual spectrum); researched this against the wiki and community discussion, and found no confirmed in-game effect either way -- what, if anything, the suffix changes is genuinely debated among players, so this map doesn't tie anything (like Ruins odds) to it.
Community-submitted data
Anything entered via Edit system is trusted as typed -- it isn't checked against Hello Games' own in-game discovery records, which are known to desync between players. Two travellers can occasionally submit different names for the same system in good faith. If something looks wrong, use Report and elegra1965 will sort it out from the save history.
Import from my save file
In Edit system, "Import from my save file" reads a real .hg save entirely in your own browser -- the file itself is never uploaded anywhere. It can find your in-game name (to auto-fill "Your name" above) and any real bases you've built, which you can then choose to bulk-import to the shared map in one go. Discovery records don't store player-given planet names at all (checked directly against a real save), only base names do, so that's the one thing this can genuinely pull in for you -- everything else still needs typing in by hand, same as always. Friend codes aren't in a save file either (that's an account/platform thing, not game data). One import per device per day, same spirit as the normal edit rate limit but scaled for a much bigger write.
New to No Man's Sky?
A "portal address" is a 12-symbol code the game uses to pin down a star system's location. Don't have one? Hit Random in the toolbar to jump somewhere, or tap Glyphs to see the code as the game's own symbols instead of letters/numbers.
Plotting a hyperdrive course
Set course / Lock navigation target plots a real multi-jump route to that system for your current hyperdrive type and range (set in Filters). Every jump always lands on a real charted star, never empty space -- same as the real game -- so the reported jump count is usually a bit above the straight-line distance-divided-by-range number, sometimes noticeably so in sparser patches of space. That's not a bug: a real star is rarely sitting exactly on your bearing at exactly your max range, so routes drift slightly to reach one, and that adds up over a long trip. No Man's Sky itself has no multi-hop route planner at all -- you'd normally do this same star-by-star checking manually, this just does it for you and shows the whole path at once. The line itself matches the real game's own convention: solid means a single jump is enough, dashed means it needs multiple hops, and red-dashed means your current drive can't reach that star's colour at all. Clicking any star while browsing automatically replots the line to it, replacing whatever was there before. If a route's hop count is well above the naive distance-divided-by-range figure, a short reminder appears right on the Course Plotted card itself, not just here -- researched this against real player reports too: NMS's own displayed hyperdrive range has long been known to overstate the actual effective jump distance (a leftover from a past galaxy-distance rescale), so needing noticeably more real hops than the raw numbers suggest is genuinely how the real game behaves, not something unique to this map.
Search by name
The Search button finds a system, planet, moon or base by name and jumps straight there -- but only among things that already have a real name attached: anything community-documented via Edit system, plus your own bookmarks, waypoints, and visited history (searched across every galaxy, not just the one you're viewing). A planet/moon/base result scrolls and highlights the matching row in the info panel once you land on the system, so you're not left hunting for it in the body list. The rest of the galaxy has no name to search until someone actually names it -- and since names aren't tied to a specific galaxy in the shared data store, the same documented address can look identical no matter which of the 257 galaxies you're browsing.
Boxes in your way?
Filters, the system info panel, and Course plotted can all be dragged by their header to wherever suits your screen -- handy on smaller or rotated phones where they can otherwise overlap.

Set your hyperdrive class

Course plotting defaults to a Standard hyperdrive, Basic range (101 LY) -- what every save starts with (confirmed against the NMS wiki: the unupgraded base range is exactly 101 LY, not a round 100). If you've upgraded your ship (Cadmium/Emeril/Indium/Atlantid drives, an S-class engine, a freighter, etc.) set your real drive type and range here, or Enter system / Jump to will warn you that a star's colour is out of reach.
Change it any time
Filters → Hyperdrive button (also sets your drive TYPE now -- see below).

Import from my save file

Your save file never leaves this device -- it's read and decoded entirely by your own browser, right here on this page. Nothing is sent anywhere unless you choose to import your real base names below, and even then only the base name(s) + system address are sent, never anything else from your save.
This only pulls in base names (and your in-game username, if found) -- that's genuinely all a save file exposes about your bases. Everything else a system can show -- flora, fauna, minerals, resources, sentinel activity, biome, rings, moons, and so on -- still needs typing in by hand via Edit system, same as always.
Where do I find this file?
A website can't open a file picker straight to a folder for you -- that's a browser security restriction, not something this site can work around -- so the dialog opens wherever your OS last left it. Most file pickers let you paste a full path into their own address/location bar to jump straight there.

Steam or GOG (Windows): %APPDATA%\HelloGames\NMS\st_<your Steam ID>\ -- paste %APPDATA%\HelloGames\NMS into the picker's address bar, then open the one folder inside it. Pick save.hg (or save2.hg/save3.hg etc for another slot -- if unsure which is current, sort the folder by "Date modified" and pick the newest one). Ignore any file starting with mf_, those are manifests, not the save itself.

Microsoft Store / Xbox Game Pass (Windows): not currently supported -- that version stores saves in a different, encrypted format this tool can't read yet. Manual entry via the form above is the only option for now.

PS4/PS5/Xbox console: saves normally live on the console itself, with no simple way to get a plain file out of a browser -- manual entry via the form above is the only option there. Exception: if you've linked your account at cloud.nomanssky.com for cross-save, you can download that cloud save onto a PC copy of the game (Steam or GOG) from the in-game Cross-Save Manager -- once it's local on your PC, the Steam/GOG path above applies to it like any other save.
Reading your save file...
Your in-game name
Friend codes aren't stored in a save file at all (they're a platform/account thing, not game data) -- you'll still need to type yours in above if you want it shown.
Real bases found in your save
Real system names found in your save
From systems you've actually renamed in-game (Discoveries screen) -- only fills in the system's name if nobody's documented it yet, never overwrites an existing one.
Real planet names found in your save
Real planets you've renamed in-game, matched to the exact body slot in that system. Only sets the name -- biome/resources/everything else stays whatever's already there (procedural, or someone else's own documentation).
All of this gets added to the shared community map, same as typing it into this form one at a time, just all at once. Anything already documented by you or another traveller is merged in (or, for names, only fills a blank slot) -- nothing existing is ever clobbered.
