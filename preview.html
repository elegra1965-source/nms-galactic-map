Before you explore

A few quick things:
Read aloud
ready
Fan-made project
This is an unofficial, fan-made tool. It is not affiliated with, endorsed by, or sponsored by Hello Games.
Procedural data
Star systems are generated procedurally from their portal address, the same way the game does -- they are not scraped from anyone's real save. Star type, system/region names, total planet+moon count, and (as of 2026-08-23) race, economy type/tier, and conflict level are all reverse-engineered from the game's own logic and right most of the time, but they're a corpus-verified approximation, not a perfect decompile -- occasional mismatches (e.g. a system that generates as 5 bodies but is really 3 in your save, or a race that doesn't match) are a known, expected gap (roughly 1 in 100, per the 1000-system real corpus this was validated against), not a bug to report. The exact sell%/buy% numbers shown are the one part of that economy panel still this project's own invented figure, not derived from the address -- the real game only exposes economy strength (low/medium/high), not an exact percentage, to reverse-engineer against. Individual planet names are not accurate at all -- the real game's planet-naming logic has never been fully reverse-engineered (confirmed against the game's own decompiled data and a real save file), so what you see is a plausible guess, not your actual save data. As of 2026-08-18 that guess leans on the planet's own biome (and Sentinel activity, once known) to pick a more fitting-sounding name -- still a guess, just a less randomly-mismatched one. Which planets have rings (and whether a planet has water) is a guess too -- No Man's Sky's real ring-placement logic has never been reverse-engineered, so unlike race/economy/conflict above, it's this project's own invented flavour, built to read naturally next to the real in-game panel. The underlying ring odds are real decompiled game data though (the flat 30% chance, pulled from GCSOLARGENERATIONGLOBALS.GLOBAL.MBIN) -- so the overall statistical feel matches the game, but any single planet's actual ring (or water) can't match your save any more than its name can. As of 2026-09-09 rings and water get the same strict treatment as Biome below rather than a tagged guess: simply not shown at all until a traveller confirms the real answer via Edit system. Sentinel activity per planet is the same kind of invented guess (added 2026-08-23) -- No Man's Sky has never exposed this per system in a way that's been reverse-engineered either, so it's this project's own weighting, leaning toward calmer readings in low-conflict systems and more aggressive ones in high-conflict systems, tagged "(procedural)" next to the value until a traveller confirms the real in-game reading via Edit system -- the one field left shown this tagged-guess way rather than hidden outright. Biome is handled differently again (2026-09-08) -- nobody has reverse-engineered No Man's Sky's real biome roll at all, so like rings and water above, this project doesn't even display a guess for it: every planet's Biome, Category type, and Conditions fields show "Unknown" until a traveller reports the real reading via Edit system, at which point that traveller's answer is shown as-is, not a procedural approximation. On the rare system where a portal address isn't available to compute the real values from, race/economy/conflict fall back to an invented guess too, same as rings -- a dashed "Procedural" tag next to the field is how you can tell. Importing your save file only ever pulls in real base names (a save doesn't expose anything else about a system) -- everything else, including fixing a wrong planet count, still needs typing in by hand via Edit system. A system only reflects real in-game data once a traveller has entered it that way, marked "Community edited".
Star class letters (e.g. "G7p")
The letter is the spectral class (matches star colour) and the digit is a sub-class. The lower-case suffix -- f, p, or pf -- borrows real astronomy terms (p = "peculiar", an unusual spectrum); researched this against the wiki and community discussion, and found no confirmed in-game effect either way -- what, if anything, the suffix changes is genuinely debated among players, so this map doesn't tie anything (like Ruins odds) to it.
Community-submitted data
Anything entered via Edit system is trusted as typed -- it isn't checked against Hello Games' own in-game discovery records, which are known to desync between players. Two travellers can occasionally submit different names for the same system in good faith. If something looks wrong, use Report and elegra1965 will sort it out from the save history. Biome and resource fields work the same way -- both now offer a fuller, wiki-researched dropdown (Biome added Water World and corrected a couple of naming gaps, 2026-08-26) with room to type your own value if what you see in-game isn't listed. Resources and Minerals were also renamed Common resources / Uncommon resources to match the wiki's own rarity split, and the same dropdown-plus-your-own-value treatment now covers Salvageable tech and Fossils & curiosities too. Typing a value that isn't on the list yet (2026-09-02) doesn't just get remembered for you -- it's added to the shared suggestion list every traveller sees, so the next person to spot the same item gets it as a dropdown option instead of having to type it themselves.
Screenshots
Edit system can now carry an optional photo alongside the public notes field -- visible to every visitor, same as everything else typed in there, and covered by the same flag/dispute system if someone thinks it's wrong or inappropriate. Pick one from your device and it's resized/compressed automatically before upload, no need to shrink it yourself first. Separately, your own private Surveyor notes (see the system info panel) can carry a photo too -- that one never leaves your device, saved locally the same way the note text already is. Both are entirely optional and only ever replace what was there if you choose a new one.
Space station directorship
Added 2026-09-09 for the real "Cosmos" 10th-anniversary update (Update 7.0), which lets you become director of a system's space station and personalise it. Like Ancient Ruins/Outlaw above, this isn't tied to any procedural rule -- it's manual-only, so use Edit system to mark a system as having a station and, if you like, give it a name and an optional photo. A director may also (2026-09-10) optionally have founded an alliance -- checked against the real patch notes first: founding one is its own separate, optional action, not tied to any single station or region, so it's tracked the same optional way as the station name itself. This is still a foundation pass: existence, name, photo, and alliance name are tracked, not any deeper director-specific detail.
Signal markers
Added 2026-09-09. The floating diamond-shaped signals you see near objects in-game -- what your own "Starmap Analysis Report" popup actually said was there -- are entirely manual, same spirit as station directorship above: an earlier version guessed one for every single planet from its biome, but a real screenshot showed every world getting a fabricated icon with nothing ever actually submitted, so that guessing was removed outright -- a marker now only ever appears once a traveller adds one via Edit system. Nine icon types are selectable (Mineral Deposit, Flora Growth, Frozen Signal, Tech Anomaly, Deep-space Outpost, Cosmic Whale, Hazard / Danger, Minor Wreckage, Atlas Station), picked from a small dropdown that shows each option's actual icon image next to its name rather than plain text. Six of the nine (Mineral Deposit, Frozen Signal, Deep-space Outpost, Cosmic Whale, Minor Wreckage, Atlas Station) now use real in-game icon images; the rest (Flora Growth, Tech Anomaly, Hazard / Danger) still use a hand-drawn placeholder glyph until a real image is available for them too. Each marker also carries a free-text name, category, signal type, and route note -- type what your own report actually said, same "type what you saw" pattern as everything else in Edit system.
Import from my save file
In Edit system, "Import from my save file" reads a real .hg save entirely in your own browser -- the file itself is never uploaded anywhere. It can find your in-game name (to auto-fill "Your name" above) and any real bases you've built, which you can then choose to bulk-import to the shared map in one go. Discovery records don't store player-given planet names at all (checked directly against a real save), only base names do, so that's the one thing this can genuinely pull in for you -- everything else still needs typing in by hand, same as always. Friend codes aren't in a save file either (that's an account/platform thing, not game data). One import per device per day, same spirit as the normal edit rate limit but scaled for a much bigger write.
New to No Man's Sky?
A "portal address" is a 12-symbol code the game uses to pin down a star system's location. Don't have one? Hit Random in the toolbar to jump somewhere, or tap Glyphs to see the code as the game's own symbols instead of letters/numbers.
Starting position
A first-ever visit lands you somewhere random -- roughly 700,000-750,000 ly from the galactic core in Euclid, matching where a fresh No Man's Sky save actually starts, not a fixed placeholder every visitor sees. It isn't a real system tied to your own save, just a reasonable place to start exploring from. Once you jump anywhere for real (typing an address, Random, a Search result, and so on), this map remembers that position -- and which of the 257 galaxies you were in -- so coming back later picks up exactly where you left off instead of starting over in Euclid. That's stored locally in your own browser only, never sent anywhere, and it clears if you clear your browser's site data. The pulsing gold ring marking it in Galaxy view is clickable -- tap or click it to drop straight into Local view at that system.
Galactic Atlas overlay
The Atlas toggle in Galaxy view overlays real points of interest from Hello Games' own Galactic Atlas website (galacticatlas.nomanssky.com), Euclid galaxy only -- around 50 community regions and planets the developers themselves have featured. Each shows as a diamond marker that orbits with the galaxy exactly like the gold "you are here" ring does; click one to open its real Atlas page in a new tab. Addresses were hand-entered once from the live site rather than scraped on every visit, so it won't reflect a brand-new Atlas addition the same day it's posted -- kept current by hand for now, same spirit as everything else community-sourced on this map. Nearby points collapse into one marker showing a count until you zoom in close enough to tell them apart, matching how the official Atlas site's own map behaves.
Plotting a hyperdrive course
Plotted course / Lock navigation target plots a real multi-jump route to that system for your current hyperdrive type and range (set in Filters), and opens the Warp Manifest showing the full jump-by-jump itinerary -- click it again on the same target to close the manifest without re-plotting. Every jump always lands on a real charted star, never empty space -- same as the real game -- so the reported jump count is usually a bit above the straight-line distance-divided-by-range number, sometimes noticeably so in sparser patches of space. That's not a bug: a real star is rarely sitting exactly on your bearing at exactly your max range, so routes drift slightly to reach one, and that adds up over a long trip. No Man's Sky itself has no multi-hop route planner at all -- you'd normally do this same star-by-star checking manually, this just does it for you and shows the whole path at once. The line itself matches the real game's own convention: solid means a single jump is enough, dashed means it needs multiple hops, and red-dashed means your current drive can't reach that star's colour at all. Clicking any star while browsing automatically replots the line to it, replacing whatever was there before. If a route's hop count is well above the naive distance-divided-by-range figure, a short reminder appears right on the Course Plotted card itself, not just here -- researched this against real player reports too: NMS's own displayed hyperdrive range has long been known to overstate the actual effective jump distance (a leftover from a past galaxy-distance rescale), so needing noticeably more real hops than the raw numbers suggest is genuinely how the real game behaves, not something unique to this map.
Galactic Navigator
PLAN JOURNEY on the Warp Manifest card takes you to a separate page -- the Galactic Navigator -- in this same tab, handing off your real plotted route: every hop's real name, portal address, region, star type, race, economy and conflict level, straight from the same algorithm this map uses everywhere else, not invented for the handoff. Close the tab or come back tomorrow and it picks your journey back up right where you left it -- saved on this device the same way bookmarks and waypoints are. One piece is still a simplified preview rather than a finished feature, though: confirming a real black-hole exit inserts that detour and resumes toward the originally planned next stop, rather than recalculating a whole new multi-hop route through the rest of your journey (2026-08-30: the exit candidates themselves are real, generated live from nms-core centred on the black hole's own real region -- it's only the re-route-the-rest-of-the-trip step that's simplified). Back to Map (mid-journey) or View Map (once finished) brings you right back to this same live map, already focused on wherever you ended up.
Saving and sharing a route
Once a course is plotted, the Course plotted card has two more buttons below Jump to / Clear. Save Route stores that exact route -- start, end, every waypoint -- into My Routes (the ☰ Routes button in the toolbar) so it's there on this device even after closing the tab; expeditions rarely get planned start-to-finish in one sitting. Copy Link hands the same route out as a URL instead, for pasting to yourself on another device or sending to someone else -- opening it loads (and saves) the route automatically, or you can paste one into the box at the top of My Routes without needing the link to open on its own. Saved routes travel with Export/Import logs the same way bookmarks and waypoints do.
Search & Scan -- also how to get back to everywhere you've been
The Search popup covers two tabs: By Name and By Traits (added 2026-09-12). By Name finds a system, planet, moon or base by name and jumps straight there -- starting with anything already community-documented via Edit system, plus your own bookmarks, waypoints, and visited history (searched across every galaxy, not just the one you're viewing). A planet/moon/base result scrolls and highlights the matching row in the info panel once you land on the system, so you're not left hunting for it in the body list. Leave the search box empty (or open By Traits with nothing ticked) and it instead lists everywhere you've bookmarked, waypointed, or visited, plus any system you personally have edited or bulk-imported from your save (tagged "Documented (you)") -- sorted alphabetically, click one to jump straight back, no address or portal glyphs to remember. This part works regardless of where you currently are.

Either tab can also run a Scan (added 2026-09-12) of the space around your current position, out to a radius that starts synced to your current hyperdrive's jump range (Filters) and stays synced until you type your own value into the radius box. Scan works differently from the name lookup above: it doesn't need a system to already be documented, bookmarked, or visited -- it generates every system it can reach the same way this map always does, and checks the real result against your query (the system's own name, or any individual planet/moon name, told apart in the result) or, on By Traits, its colour/race/economy/black-hole/Atlas/outlaw/giant status. That means a name from a friend's save or a screenshot can genuinely turn up here now even for a system nobody's ever visited or edited on this site -- as long as it's within your scan radius. With no name typed and no trait ticked, Scan instead just lists whatever's nearby, nearest first, for browsing the neighbourhood rather than looking for something specific. Clicking any result opens its info panel and quietly plots a course to it without navigating away, so browsing results never costs you whatever route you already had plotted.

Local view's Filters panel is different again -- it only ever narrows down whatever's already rendered nearby (colour, race, economy, black holes, Atlas interfaces, outlaw/phantom/shadow systems, waypointed, reachable-by-drive), so there's no "Visited" or "Edited by traveller" filter option there any more -- a system on the other side of the galaxy was never going to appear just because a filter box was ticked, so Search/Scan above is the actual way to get back to it, or out to it. Beyond your scan radius, the rest of the galaxy still has no name to look up unless someone's actually named it here first -- that part hasn't changed: turning a portal address into a name is a one-way calculation (like a hash), so there's no formula to run backwards from a name to an address once you're past scan range, only generating addresses forward to see what they produce. If you have the actual portal address instead of just a name, typing or pasting it into the address box and hitting Jump always works at any distance, since generating a system forward from its address is the one direction this map can always compute. And since names aren't tied to a specific galaxy in the shared data store, the same documented address can look identical no matter which of the 257 galaxies you're browsing.
Boxes in your way?
Filters, the system info panel, Course plotted, the glyph keypad, Search, Edit system, and Accessibility can all be dragged by their header to wherever suits your screen -- handy on smaller or rotated phones where they can otherwise overlap.

Course plotting defaults to a Standard hyperdrive, Basic range (101 LY) -- what every save starts with (confirmed against the NMS wiki: the unupgraded base range is exactly 101 LY, not a round 100). If you've upgraded your ship (Cadmium/Emeril/Indium/Atlantid drives, an S-class engine, a freighter, etc.) set your real drive type and range here, or Enter system / Jump to will warn you that a star's colour is out of reach.

Import from my save file

Your save file never leaves this device -- it's read and decoded entirely by your own browser, right here on this page. Nothing is sent anywhere unless you choose to import your real base names below, and even then only the base name(s) + system address are sent, never anything else from your save.
This only pulls in base names (and your in-game username, if found) -- that's genuinely all a save file exposes about your bases. Everything else a system can show -- flora, fauna, minerals, resources, sentinel activity, biome, rings, moons, and so on -- still needs typing in by hand via Edit system, same as always.
Where do I find this file?
A website can't open a file picker straight to a folder for you -- that's a browser security restriction, not something this site can work around -- so the dialog opens wherever your OS last left it. Most file pickers let you paste a full path into their own address/location bar to jump straight there.

Steam or GOG (Windows): %APPDATA%\HelloGames\NMS\st_<your Steam ID>\ -- paste %APPDATA%\HelloGames\NMS into the picker's address bar, then open the one folder inside it. Pick save.hg (or save2.hg/save3.hg etc for another slot -- if unsure which is current, sort the folder by "Date modified" and pick the newest one). Ignore any file starting with mf_, those are manifests, not the save itself.

Microsoft Store / Xbox Game Pass (Windows): not currently supported -- that version stores saves in a different, encrypted format this tool can't read yet. Manual entry via the form above is the only option for now.

PS4/PS5/Xbox console: saves normally live on the console itself, with no simple way to get a plain file out of a browser -- manual entry via the form above is the only option there. Exception: if you've linked your account at cloud.nomanssky.com for cross-save, you can download that cloud save onto a PC copy of the game (Steam or GOG) from the in-game Cross-Save Manager -- once it's local on your PC, the Steam/GOG path above applies to it like any other save.
